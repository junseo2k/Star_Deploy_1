# 저장 및 실행 안정성 변경

- 저장 버전 1: 기업·시대·예약 사건은 에셋 GUID 기반 ID로 연결한다. 기존 무버전 파일은 이름/인덱스로 읽고 다음 저장부터 ID를 기록한다. 기존 파일에서 누락된 뉴스·차트·NPC 이력은 복구할 수 없다.
- 뉴스 효과·대기 소문·가격 이력·분기 비교값·진행 사업·NPC 보유 및 예측 이력을 저장한다. Unity 객체 instanceID는 저장 파일에 사용하지 않는다.
- 거래와 다음 날 진행을 자동 저장한다. 학습/자동 시뮬레이션은 슬롯을 자동으로 덮어쓰지 않는다. 버튼과 시뮬레이션 동작 자체는 유지한다.
- 저장은 같은 디렉터리의 임시 파일을 완성한 후 교체한다. 이전 정상 파일은 `.bak`으로 보관한다. 손상 시 백업을 시도하고, 지원하지 않는 최신 버전은 이전 백업으로 임의 롤백하지 않는다.
- 수동 저장 실패 시 완료 팝업과 선택 슬롯을 변경하지 않는다. 손상 파일을 직접 로드한 경우 자동 저장을 차단한다.
- 플레이어/NPC 현금·대출·평가액·거래 대금을 64비트로 계산한다. 기업별 int 필드는 범위를 제한해 오버플로로 부호가 바뀌지 않게 한다.
- 일반 릴리스에서는 상세 로그와 자동 CSV 수집을 제외한다. 명시적인 학습 실행은 CSV를 생성하며 파일 오류는 게임 진행을 중단하지 않는다.

## 반복 가능한 검사

Unity에서 플레이 모드를 종료하고 **Tools → Validation → Run Save and Economy Checks**를 실행한다.

실제 슬롯을 사용하지 않고 임시 디렉터리에서 다음을 검사한다:

1. 구버전 매출 필드 누락과 0/음수 매출 보존
2. 큰 금액·가격 이력의 저장과 원자적 교체·백업 복원
3. 잘못된 데이터/쓰기 실패 시 원본 보존 및 미래 버전 거부
4. 기업 이름 변경과 사건 배열 재정렬 후 ID 연결
5. 큰 거래 대금·합산 한계·화면 모드 매핑
6. 생성형/대기 뉴스와 NPC 이력 복원
7. NPC 상장폐지 보유분 정리와 모델 초기화 오류 격리
8. 전체 복원 경로의 보유량·기업 재무·사업·NPC 상태
9. 콘텐츠 에셋의 고정 ID 유효성

11개 검사 결과는 `Library/BuildReadinessChecks.json`에 기록된다.

실제 Windows 실행 파일에서의 화면 모드 전환, 입력, NPC ONNX 추론 성능은 별도 플레이 검증 대상이다. C# 에디터/비에디터 분기 컴파일은 실행 파일 패키징 검증을 대신하지 않는다.
