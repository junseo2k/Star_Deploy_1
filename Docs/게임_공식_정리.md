## 0. 하루가 지날 때 벌어지는 순서

`GameManager.OnNextDayButton()` — **이 순서 자체가 공식**입니다. 바꾸면 결과가 달라집니다.

```
① 오늘 알림 비우기
② 활성 뉴스 진행        Rday--, 뉴스경과일++
③ 소문 대기열 진행      daysLeft--, 0이면 진짜 뉴스로 전환
④ 날짜 +1
⑤ 대출 이자 차감
⑥ 소형 뉴스 생성 시도
⑦ 예약된 전조/대형 뉴스 발생
⑧ 시대 힌트·시작·종료
⑨ 시대 주가 보정         ← 주가 변동
⑩ 10일마다 분기 결산     ← 주가 변동 (실적 발표)
⑪ 일일 랜덤 변동         ← 여기서 "어제 가격"을 기록
⑫ 활성 뉴스 주가 효과    ← 주가 변동
⑬ 지속일 끝난 뉴스 제거
⑭ NPC 매매
⑮ 히스토리 기록 → 게임오버 판정 → CSV 저장 → 총자산 갱신
```

> ⚠️ **⑪에서 "어제 가격"을 찍습니다.**
> 그래서 ⑨(시대)와 ⑩(실적 발표)로 움직인 주가는 그날 등락률에 안 잡힙니다.
> 실적 발표일에 주가가 크게 뛰어도 화면의 % 는 조용해 보이는 이유입니다.

## 1. 회사가 버는 돈

```
수입 income = round(평소매출 runtimeRevenue × 시대배율) − 운영비 operatingCost

시대배율 = 유망 산업 1.2 / 무관 1.0 / 비선호 산업 0.8
```

| 값 | 정체 |
|---|---|
| `baseRevenue` | 인스펙터 고정. 게임 중 절대 안 변함 |
| `runtimeRevenue` | 실제로 쓰이는 매출. 시작 시 `baseRevenue`, 사업 성공/실패로만 영구 변동 |
| `operatingCost` | 고정 지출. 시대 배율이 안 걸림 → 그래서 시대 효과가 증폭됨 |
| `income` | 매턴 다시 계산되는 파생값. 저장 안 함 |

운영비에 배율이 안 걸리는 것이 체감의 핵심입니다.
매출 100 / 운영비 70이면 평소 수입 30, 시대 수혜 시 120 − 70 = 50 → 매출은 20% 올랐는데 수입은 67% 뜁니다.
**운영비가 무거운 회사일수록 사업보다 시대가 실적을 더 크게 흔듭니다.**

### 금고 (`runtimeAsset`)

```
게임 시작 금고 = baseAsset > 0 ? baseAsset : 운영비 × 생존분기수

생존분기수: 안정형 4 / 자원형 5 / 고위험형 8 / 성장형 10

분기마다:  금고 += 수입           (적자면 음수가 더해져 줄어듦)
           금고 -= 배당총액
           금고 -= 사업 투자비
           금고 += 사업 성공 시 assetBoost
```

## 2. 분기 결산 (10일마다)

```
분기 마감일인가?   현재날짜 % 10 == 0
현재 몇 분기?      (현재날짜 − 1) / 10 + 1
```

`SettleQuarter()` 처리 순서 — 이 순서에도 이유가 있습니다.

```
① 수입 확정            (시대 배율 반영)
② 사업 성공·실패 판정   → 매출이 바뀜
③ 수입 재확정          (사업 결과 반영)
④ 금고 += 수입
⑤ 배당 지급           (금고에서 나감)
⑥ 부도·상장폐지 판정    (배당까지 빠진 최종 금고로)
⑦ 새 사업 착수 판정     (남은 금고를 보고 결정)
⑧ 진행 중 사업 알림
⑨ 실적 공시           (지난 분기 대비)
⑩ 주가를 목표가로 끌어당김
```

⑦을 ⑤·⑥ 뒤에 두는 이유: 배당으로 나갈 돈까지 투자비로 써버리면
"금고 바닥 → 사업 줄임"이 성립하지 않습니다.

## 3. 사업

### 착수 판정 (분기 마감일, 회사당 딱 한 번)

```
이미 사업 중이면           → 안 함
금고가 마이너스면          → 안 함
착수 확률: 재투자형 35% / 배당형 18%
안전 마진 = 운영비 × 2
후보 조건: 금고 − 투자비 ≥ 안전 마진
후보 중 하나를 무작위로 선택
```

회사당 한 번만 판정합니다. 사업 목록을 돌며 하나씩 판정하면
사업을 많이 가진 회사만 착수 확률이 배로 뛰기 때문입니다.

### 결과 판정 (기간이 다 찬 분기)

```
성공 여부 = Random(0~99) < successRate

성공 →  매출 += revenueBoost
        금고 += assetBoost
실패 →  매출 -= revenueDrop       (투자비는 이미 날아감)
```

투자비는 착수할 때 한 번에 빠져나가고, 진행 중에는 아무 일도 안 일어납니다.

## 4. 주가를 움직이는 5가지

주가가 변하는 경로는 딱 이것뿐입니다.

### ① 일일 랜덤 변동 (매일)

```
변동폭 = 안정형 ±0.5% / 보통형 ±1.0% / 고변동형 ±1.5%
오늘변동 = Random(−변동폭, +변동폭) + 0.15     ← 0.15%는 매일 붙는 상승 편향
새 주가 = round(현재가 × (1 + 오늘변동/100))
```

> ⚠️ `Stock.cs`의 `VolatilityType` 주석에 "안정형 −1.5%~+1.5%"라고 적혀 있는데
> 실제 상수와 다릅니다. 실제로 도는 값은 위의 0.5 / 1.0 / 1.5입니다.

### ② 시대 주가 보정 (시대 진행 중 매일)

```
유망 산업:   주가 × (1 + Era.boostedRate/100)
비선호 산업: 주가 × (1 − Era.weakenedRate/100)
```

**시대는 두 군데를 따로 때립니다** — 여기(매일 주가 직접)와
1장의 수입 배율(분기당 ×1.2 / ×0.8). 별개의 장치입니다.

### ③ 소형 뉴스

```
감쇠율 rate = lowPercent[뉴스경과일]         (배열 범위 밖이면 0 = 효과 없음)
새 주가 = round(현재가 × (1 + Random(min, max+1)/100 × rate))

연쇄 효과 (뉴스 2일차에만):
새 주가 = round(현재가 × (1 + Random(priceMin, priceMax)/100 × rate))
```

기본 감쇠 배열은 `{1.0, 0.4}` — 첫날 100%, 둘째 날 40%.

### ④ 대형 뉴스

산업군별로 표를 찾고, 당사국이냐 아니냐로 값이 갈립니다.

```
당사국   → changePriceMin    ~ changePriceMax
비당사국 → changePriceMinNon ~ changePriceMaxNon

새 주가 = round(현재가 × (1 + Random(min, max+1)/100 × rate))
```

### ⑤ 재무 중력 (분기 마감일에만)

```
개선도 = (수입 − 기준수입) / max(기준매출, 1)
         기준수입 = baseRevenue − operatingCost
         기준매출 = baseRevenue

배수 = clamp(1 + 개선도 × 2.0,  0.3,  3.0)
목표주가 = round(StockBasePrice × 배수)

차이 = 목표주가 − 현재가
이동 = round(차이 × 0.30)           ← 한 번에 30%만 좁힘
이동이 0이면 최소 ±1G는 움직임       ← 안 그러면 저가 종목이 영영 멈춤
```

나누는 쪽을 매출로 쓰는 이유: 수입으로 나누면 평소 적자인 성장형에서
① 기준 수입이 0 이하일 때 계산이 안 되고 ② 음수끼리 나눠 부호가 뒤집힙니다.

**모든 주가에 공통 하한: 1G**

## 5. 배당

```
조건: hasDividend == true 이고 수입 > 0

배당총액 = round(수입 × dividendRate)
         → 금고보다 크면 금고만큼만 (금고가 마르면 배당 중단)

금고 -= 배당총액
주당배당 = 배당총액 / 발행주식수
내가 받는 돈 = round(주당배당 × 내 보유수량)
```

재원은 **수입**으로 정하고, 실제 돈은 **금고**에서 뺍니다. 주가와는 무관합니다.

---

## 6. 부도 · 상장폐지

```
매 분기:
  금고 ≥ 0  →  연속마이너스분기 = 0      (극적으로 살아남)
  금고 < 0  →  연속마이너스분기 += 1

1~2분기 → "[경고]"
3~4분기 → "[부도 위기]"
5분기   → 상장폐지
```

상장폐지 시 보유 주식은 **전액 손실**(골드 지급 없음),
진행 중 사업 삭제, 그 회사 전용 뉴스 삭제, 목록·상세 패널에서 제거.

## 7. 매매 — 슬리피지

많이 살수록 비싸게 사고, 많이 팔수록 싸게 팝니다.

```
충격비율 = 거래수량 / 발행주식수

매수 종료가 = max(1, round(현재가 × (1 + 충격비율)))
매도 종료가 = max(1, round(현재가 × (1 − 충격비율)))

체결가 = (현재가 + 종료가) / 2        ← 시작과 끝의 평균
총액   = round(체결가 × 수량)

거래 후 주가 = 종료가                 ← 내 거래가 실제로 주가를 움직임
```

**최대 매수 가능 수량은 공식이 없습니다.**
1주씩 늘려가며 총액이 골드를 넘는 순간 멈추는 방식입니다
(슬리피지 때문에 나눗셈으로는 못 구함).

### 평균 매수 단가

```
새 평단 = (기존평단 × 기존수량 + 이번총액) / (기존수량 + 이번수량)
```

판매할 때는 평단을 안 건드립니다.

## 8. 플레이어 자산

```
총자산    = 현재골드 + 보유주식 평가금액
평가금액  = Σ (현재가 × 보유수량)
매수원금  = Σ (평단 × 보유수량)

전체 손익률 = (평가금액 − 매수원금) / 매수원금 × 100
종목 손익률 = (현재가 − 평단) / 평단 × 100
```

원금이 0이면 0%로 처리합니다.

---

## 9. 대출

```
대출 한도  = 현재골드 / 2             (정수 나눗셈, 50%)
턴당 이자  = ceil(대출금 × 0.01)      (1%, 올림)

매일 골드에서 이자만 빠짐 — 원금은 안 줄어듦
상환은 수동, 보유 골드보다 많이는 못 함
```

## 10. 게임 오버

```
① 골드 ≤ 1000 이 5턴 연속
② 대출금 > 0 이면서 골드 < 대출금     (상환 불가)
```

둘 중 하나면 즉시 GameOver 씬으로.

## 11. 뉴스 발생 주기

### 소형 뉴스

```
매일 타이머 += 1
매일 3~5 중 하나를 새로 뽑아서 비교
타이머 ≥ 뽑은 수  →  뉴스 발생, 타이머 = 0
```

타이머 3일차 1/3 확률, 4일차 2/3, 5일차는 무조건. 평균 4일 정도입니다.

**불확정 뉴스(소문)** — 생성 즉시가 아니라 **2턴 뒤**에 효과 발동.

### 대형 뉴스

```
다음 발생일 = 현재날짜 + Random(30, 51)       → 30~50턴 뒤

전조 뉴스일 = 대형뉴스일 − (전조 지속일 + 1)
              전조 지속일이 없으면 2를 씀
```

전조 뉴스가 대형 뉴스 직전에 딱 끝나도록 지속일만큼 앞당겨 배치합니다.

## 12. 시대

```
최초 시작 가능일: 20일
지속: 15턴
종료 후 휴지기: 5턴   →  다음 시대는 종료일 + 5

힌트 뉴스: 시작 2일 전에 미리 뜸 (이때 다음 시대가 확정됨)
```

**주기는 20턴 = 2분기**입니다. 분기(10턴)와 안 맞물려서,
시대가 분기 중간에 들어왔다 나갑니다.

## 13. NPC 투자자 (LSTM)

```
입력: 최근 10일 × [정규화 가격, 등락률, 뉴스영향여부(0/1)]
정규화 가격 = (그날가격 − 10일 최저) / (10일 최고 − 10일 최저)
              최고 == 최저면 예측 스킵

모델 출력 = 다음날 예상 변동률

전 종목 예측이 끝난 뒤:
  평균 = 모든 예측의 평균
  차이 = 이 종목 예측 − 평균

  차이 > +0.02  →  매수
  차이 < −0.02  →  매도

매수 예산 = floor(NPC골드 × 0.5)
매수 수량 = 예산 / 현재가           (정수 나눗셈)
매도      = 전량
```

> NPC의 매매는 **주가에 아무 영향을 안 줍니다.** 자기 골드와 보유량만 바뀝니다.
> 플레이어 매매만 슬리피지로 주가를 움직입니다.

## 14. 기타 표시값

```
등락률        = (현재가 − 어제가) / 어제가 × 100      (어제가 ≤ 0이면 0)
시가총액      = (long)현재가 × 발행주식수             ← long 캐스팅 필수 (21억 넘침)
가짜 거래량   = |등락률| × 50
히스토리 길이 = 10일 (넘으면 앞에서 하나씩 버림)
실적 공시 기준 = |수입 변화율| ≥ 3% 일 때만 알림
그래프 탭 잠금 = 10일차부터 해금 (HISTORY_LENGTH와 같은 값을 씀)
```

## 16. 알아둘 것

**주가를 움직이는 것은 수입 하나입니다.**
금고는 회사의 체력이지 가치 평가 요소가 아니라서 목표 주가 계산에 안 들어갑니다.
금고를 주가에 반영하면 배당을 줄수록·사업을 시작할수록 주가가 떨어지는 역설이 생깁니다.

**저장되는 값과 안 되는 값**

| 저장됨 (JSON) | 저장 안 됨 (매번 다시 계산) |
|---|---|
| 골드, 날짜, 대출금 | `income` — 매출·운영비로 재계산 |
| 주가, 보유 수량, 평균 매수 단가, 즐겨찾기 | `lastQuarterIncome` — 실적 공시 비교 기준 |
| `runtimeRevenue`, `runtimeAsset` | 히스토리 3종 (가격·등락률·거래량) |
| `negativeQuarters`, `isDelisted` | 시대 배율 기억용 캐시 |
| 진행 중 사업 목록, 뉴스 스케줄, 시대 상태 | |

`Stock`은 ScriptableObject라 에디터에서 값이 눌어붙습니다.
그래서 불러오기 전에 `ResetStocksToBase()`로 항상 인스펙터 기준값으로 되돌립니다.

**고칠 거리 (동작에는 문제없음)**

- `Stock.cs`의 `VolatilityType` 주석이 실제 상수와 안 맞음
  (주석 −1.5 / −2.5 / −4 vs 실제 0.5 / 1.0 / 1.5)
