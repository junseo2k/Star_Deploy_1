| 기획이 요구하는 것 | 현재 코드 | 할 일 |
|---|---|---|
| 분기 수입 = 평소 매출 − 운영비 | `Stock.baseIncome` 하나 (이미 뺀 결과만 있음) | 칸을 두 개로 쪼갠다 |

| 나쁜 체질은 시작 금고를 두껍게 | 금고 비어 있으면 `수입 × 10` | 체질별 공식으로 교체 |
| 금고 마이너스 = 빚 | 마이너스는 되지만 아무 일도 안 일어남 | 새로 만든다 |
| 3분기 경고 / 5분기 상장폐지 | 없음 | 새로 만든다 |

| 대형 사업은 2~3분기 | 칸은 있는데 40개 전부 1분기 | 값만 고친다 |
| 성공하면 **평소 매출**이 영구히 오른다 | `incomeBoost`가 순수입에 바로 붙는다 | 붙는 대상을 매출로 옮긴다 |
| 실패하면 투자금 거의 못 건진다 | 전액 소멸 | **이미 기획대로다** |
| 상폐 자리에 새 회사 상장 | 없음 | 후순위 (Step 8) |

## 1. 먼저 알아야 할 것 — 지금 코드는 적자 회사를 굴리지 못한다

새 기획의 핵심은 **성장형(평소엔 적자인 회사)** 입니다. 그런데 지금 코드에 적자 회사를 넣으면 두 군데가 조용히 망가집니다. 다른 작업보다 이게 먼저입니다.

### ① 시작 금고가 10G가 된다 — `Stock.cs:59`

```csharp
public int BaselineAsset => baseAsset > 0
    ? baseAsset
    : Mathf.Max(BaselineIncome, 1) * AUTO_ASSET_MULTIPLIER;
```

`Mathf.Max(수입, 1)` 이 걸려 있어서, 평소 수입이 −20,000인 회사의 금고는 `1 × 10 = 10G`가 됩니다. 기획은 "나쁜 체질일수록 금고를 두껍게 줘서 몇 분기 버티게 한다"인데, 정반대로 첫 분기에 바로 마이너스로 떨어집니다.

### ② 망가지는 회사의 주가가 오른다 — `GameManager.cs:1131`

```csharp
float profitScore = stock.BaselineIncome > 0
    ? (float)stock.income / stock.BaselineIncome
    : 1f;
```

목표 주가를 **"시작 대비 몇 배"** 라는 나눗셈으로 구하고 있습니다. 여기서 두 가지 문제가 납니다.

- 기준 수입이 0 이하인 회사는 `1f` 고정입니다. 즉 **성장형 회사는 사업이 성공해도 주가가 1원도 안 움직입니다.** 사업 시스템이 그 회사에는 아예 없는 것과 같습니다.
- 기준 수입이 음수인 채로 나눗셈이 돌면 부호가 뒤집힙니다. 기준 −50,000 → 지금 −100,000 (적자가 두 배로 커짐) 이면 `profitScore = 2.0`, 목표 주가가 **2배**가 됩니다. 무너지는 회사 주가가 폭등합니다.

> 그래서 순서가 "체질 칸 추가 → 계산식 교체"가 아니라, **칸을 만들고 곧바로 계산식을 갈아치운 뒤 여기서 한 번 검증**하고 다음으로 넘어가야 합니다. 이 두 단계를 한 묶음(Step 1 + Step 2)으로 봅니다.

## Step 1. `Stock`에 체질 칸 만들기

### 무엇을

`Stock.cs`에 네 가지를 추가합니다.

| 새 칸 | 의미 |
|---|---|
| `baseRevenue` | 평소 매출 — 사업 안 해도 장사로 들어오는 돈 (항상 양수) |
| `operatingCost` | 운영비 — 매 분기 나가는 돈 (월급, 유지비) |
| `companyType` | 체질 enum: `Stable`(안정) / `Resource`(자원) / `HighRisk`(고위험) / `Growth`(성장) |
| `payoutStyle` | 성향 enum: `Dividend`(배당형) / `Reinvest`(재투자형) |

그리고 런타임 값의 **의미**를 옮깁니다. 사업이 올리는 것은 순수입이 아니라 평소 매출이므로:

```
runtimeBaseIncome  →  runtimeRevenue   (사업 성패가 누적되는 "평소 매출")
```

분기 수입 계산은 `RecalculateFinancials()` (`GameManager.cs:966`) 에서:

```csharp
// 시대는 매출만 밀어주거나 누른다. 운영비는 시대와 무관하게 그대로 나간다
int revenue = Mathf.RoundToInt(stock.runtimeRevenue * revenueModifier);
stock.income = revenue - stock.operatingCost;
```

### 왜 이렇게 나누나

**시대 배율을 매출에만 걸면 기획 5장의 "자기 시대가 오면 몰아서 번다"가 공식에서 저절로 나옵니다.**

매출 100 / 운영비 90인 성장형 회사를 보면:

| 상황 | 매출 | 운영비 | 수입 |
|---|---|---|---|
| 평소 | 100 | 90 | **+10** |
| 좋은 시대 (매출 ×1.2) | 120 | 90 | **+30 (3배)** |
| 나쁜 시대 (매출 ×0.8) | 80 | 90 | **−10 (적자)** |

운영비가 고정이라서 매출이 20% 흔들리면 수입은 200% 흔들립니다. 반대로 매출 100 / 운영비 30인 안정형은 시대가 와도 수입이 70 → 90 정도로 완만합니다. **체질별 성격이 별도 로직 없이 이 뺄셈 하나에서 나옵니다.** 지금처럼 순수입에 배율을 곱하면 모든 회사가 똑같이 ±20% 흔들릴 뿐입니다.

### 기존 40개 값을 안 날리는 이행 방법

`baseIncome`을 바로 프로퍼티로 바꾸면 인스펙터에 입력해둔 40개 값이 전부 사라집니다. 그러니 두 단계로 갑니다.

1. `baseRevenue` / `operatingCost` 를 **추가**하고 `baseIncome`은 그대로 남긴다
2. 40개 값을 채운다 — `baseRevenue = 기존 baseIncome + operatingCost` 로 잡으면 지금 수입이 유지되므로 밸런스가 안 흔들린다
3. 계산이 새 칸만 쓰게 바꾼 뒤, 마지막에 `baseIncome`을 지운다

### 만지는 파일

- `Assets/Scripts/Stock.cs` — 칸 추가, `BaselineIncome` / `BaselineAsset` 정리
- `Assets/Scripts/GameManager.cs:966` `RecalculateFinancials()`
- `Assets/Scripts/GameManager.cs:317` `ResetStocksToBase()` — `runtimeRevenue = baseRevenue`
- `Assets/Scripts/GameManager.cs:126` `StockSaveData` — `baseIncome` 필드가 이제 매출을 뜻하게 됨 (아래 주의)

> **세이브 주의**: `StockSaveData.baseIncome`에 저장된 값의 의미가 달라집니다. 개발 중이니 기존 세이브를 버리는 게 제일 깔끔합니다. 남기려면 필드를 `baseRevenue`로 새로 만들고 옛 필드가 0이 아닐 때만 변환해서 읽으세요.

### 끝났는지 확인

`AutoSimulate(200)` 을 돌려서, 흑자 종목들의 분기 수입이 이전과 **같은 값**으로 나오면 성공입니다. (아직 체질 값을 넣기 전이므로 숫자가 바뀌면 안 됩니다.)

## Step 2. 목표 주가 계산식을 적자 회사도 되게 바꾸기

### 무엇을

`GetFairPrice()` (`GameManager.cs:1128`) 의 나눗셈을 **뺄셈**으로 바꿉니다.

```csharp
// 기존: 시작 대비 "몇 배"  → 적자 회사에서 부호가 뒤집힌다
// 변경: 시작 대비 "얼마나 늘었나"를 매출 규모로 나눈다 (매출은 항상 양수)
float improvement = (float)(stock.income - stock.BaselineIncome)
                    / Mathf.Max(stock.baseRevenue, 1);
float multiplier = 1f + improvement * PROFIT_SENSITIVITY;
multiplier = Mathf.Clamp(multiplier, FAIR_PRICE_MIN_RATIO, FAIR_PRICE_MAX_RATIO);
```

### 왜

- 나누는 쪽(매출)이 **항상 양수**라 부호가 뒤집히지 않습니다. 적자가 커지면 `improvement`가 음수 → 주가가 내려갑니다. 정상입니다.
- 적자가 −100,000에서 −40,000으로 **줄어드는 것도 "개선"으로 잡힙니다.** 기획 4장의 "부도 위기에서 살아나면 대박"이 여기서 작동합니다. 지금 코드로는 이게 불가능합니다.
- 실적이 그대로면 `improvement = 0` → 곱수 1 → 목표가 = 기준가. **기존 흑자 종목 밸런스는 안 건드립니다.** 기존 문서 5장에서 지키려던 원칙이 그대로 유지됩니다.

`PROFIT_SENSITIVITY` 는 새 상수입니다. 매출 대비 수입 변화폭이 작은 안정형도 주가가 반응해야 하므로 **2.0 근처에서 시작**해서 체감 보고 조정하세요. `PROFIT_WEIGHT` / `ASSET_WEIGHT`(`GameManager.cs:85-86`)는 이 식에서 역할이 없어지므로 정리합니다.

### 같이 고치는 것 — 체질별 시작 금고

```csharp
// 나쁜 체질일수록 두껍게. 적자 회사도 몇 분기는 버텨야 기회가 온다
public int BaselineAsset => baseAsset > 0
    ? baseAsset
    : Mathf.Max(operatingCost, 1) * SurvivalQuarters;   // 운영비 기준으로 잡는다
```

`SurvivalQuarters`를 체질에 따라 다르게 줍니다 (안정 4분기 / 자원 5 / 고위험 8 / 성장 10 정도로 시작). **수입이 아니라 운영비 기준으로 잡는 이유**: "몇 분기를 버티는가"가 곧 금고 ÷ 운영비이기 때문입니다. 적자 회사도 음수가 안 끼어들어 계산이 안전합니다.

### 끝났는지 확인

체질 값을 넣은 시험용 회사 2~3개(성장형 포함)를 만들고 `AutoSimulate(200)`:

- `stock_history.csv` 에서 성장형 회사가 **사업 성공 후 주가가 오르는지**
- 적자가 커질 때 주가가 **내려가는지** (올라가면 부호가 아직 뒤집힌 것)
- 기존 흑자 종목 주가 곡선이 수정 전과 비슷한지

## Step 3. 금고 · 부도 · 상장폐지

### 무엇을

`Stock`에 두 개 추가 (둘 다 `[System.NonSerialized]`, 저장은 따로):

| 칸 | 의미 |
|---|---|
| `negativeQuarters` | 금고가 연속으로 마이너스인 분기 수 |
| `isDelisted` | 상장폐지됨 |

새 함수 `CheckSolvency()` 를 만들고 **`SettleQuarter()` 순서를 다시 짭니다.** 지금 `ProcessBusinesses()`가 "결과 판정"과 "신규 착수"를 한 함수에서 하고 있는데, 이걸 **둘로 쪼개야** 합니다.

```
① RecalculateFinancials     이번 분기 수입 확정
② ResolveBusinesses         진행 중인 사업 성공·실패 판정      ← 쪼갠 앞쪽
③ RecalculateFinancials     바뀐 매출을 수입에 반영
④ AccumulateAssets          수입을 금고에 넣는다
⑤ PayDividends              배당 지급
⑥ CheckSolvency             금고 확인 → 경고 / 상장폐지        ← 신규
⑦ StartNewBusinesses        새 사업 착수                      ← 쪼갠 뒤쪽
⑧ AnnounceQuarterResults    실적 공시
⑨ ApplyFinancialGravity     주가에 반영
```

**착수(⑦)를 배당(⑤)과 부도 판정(⑥) 뒤로 옮기는 이유**: 기획 4장의 "금고 바닥 → 배당 멈추고 사업 줄임"을 지키려면, 배당까지 다 빠져나간 **최종 금고**를 보고 착수를 결정해야 합니다. 지금처럼 맨 앞에서 착수하면 아직 배당 나갈 돈까지 투자비로 써버립니다.

### `CheckSolvency()` 가 하는 일

```
금고 >= 0        → negativeQuarters = 0  (카운트 초기화)
금고 < 0         → negativeQuarters++
   1분기째       → "[경고] 금고가 마이너스입니다"
   3분기째       → "[부도 위기] ..." (기획 4장)
   5분기째       → 상장폐지
```

카운트 초기화가 들어 있어서 기획대로 "위기에서 극적으로 살아나는" 이야기가 나옵니다.

### 상장폐지 처리 체크리스트

여기가 실수 나기 제일 쉬운 곳입니다. 빠뜨리면 없는 회사에 뉴스가 붙거나 배당이 나갑니다.

- [ ] `Portfolio.SetHolding(stock, 0, 0)` — 보유 주식 전액 손실, **골드 지급 없음** (기획대로)
- [ ] `activeBusinesses`에서 그 회사 사업 제거
- [ ] `activeNewsList` / `pendingNewsList`에서 그 회사 걸린 뉴스 제거
- [ ] `isFavorite = false`, `runtimeIssues.Clear()`
- [ ] `DetailPanel`이 그 회사를 열고 있으면 닫기
- [ ] 슬롯/탭 목록 갱신 (`SlotManager`, `TabManager`)
- [ ] `StockSaveData`에 `isDelisted` 저장 필드 추가
- [ ] `ResetStocksToBase()`에서 `isDelisted = false`, `negativeQuarters = 0` — **ScriptableObject라 안 지우면 다음 플레이로 새어나갑니다** (기존 문서 7장의 그 함정)

### 순회를 한 곳으로 모으기 (권장)

상폐된 회사를 건너뛰어야 하는 곳이 이만큼 있습니다:

`RecalculateFinancials` / `AccumulateAssets` / `PayDividends` / `ApplyDailyDrift` / `ApplyActiveNewsEffects` / `ApplyEraPriceEffects` / `ApplyFinancialGravity` / `AnnounceQuarterResults` / `RecordStockHistories` / `SaveStockDataToCSV` / `RunNpcInvestors` / 슬롯 생성

### 끝났는지 확인

일부러 운영비를 매출보다 크게 준 시험 회사를 하나 넣고 `AutoSimulate(100)`:

## Step 4. 사업을 "회사당 여러 개"로 바꾸기

### 무엇을

지금은 **사업이 회사를 가리킵니다** (`BusinessProject.targetStock`). 그래서 `GameManager`가 사업 40개를 돌면서 각각 주사위를 굴립니다 (`GameManager.cs:1029`).

이 상태로 회사당 사업을 3개로 늘리면 **그 회사만 착수 확률이 3배**가 됩니다. 사업 많은 회사가 일방적으로 유리해집니다.

방향을 뒤집습니다 — **회사가 사업 목록을 가집니다.**

```csharp
// Stock.cs
public BusinessProject[] businesses;   // 이 회사가 벌일 수 있는 사업들
```

```
회사마다 한 번만 주사위를 굴린다
  → 걸리면 businesses 중에서 하나를 뽑는다 (금고로 감당 가능한 것 중에서)
```

이러면 사업이 몇 개든 **회사당 착수 확률은 똑같습니다.** 기획 3장의 "광산이 광산만 파면 질리니까"를 만족하면서 확률은 공평합니다.

### 같이 고치는 이름

| 이전 | 이후 | 이유 |
|---|---|---|
| `incomeBoost` | `revenueBoost` | 성공하면 **평소 매출**이 오른다 (기획 3장) |
| `incomeDrop` | `revenueDrop` | 실패도 매출 쪽에 붙는다 |
| `targetStock` | (삭제) | 회사가 사업을 가리키므로 필요 없다 |

`ActiveBusiness`에 `totalQuarters`도 추가하세요. 진행률 표시(Step 7)에 "3분기 중 1분기 남음"을 쓰려면 전체 기간을 알아야 합니다.

### 에셋 작업

에셋 40개의 `targetStock` 연결이 사라지고, 대신 `Stock` 40개의 `businesses` 배열에 드래그해야 합니다. **회사 쪽에서 사업을 끌어다 넣는 것으로 방향이 바뀝니다.** 지금처럼 `GameManager.allBusinessProjects`에 등록하는 절차는 없어집니다 (등록 빠뜨려서 사업이 안 뜨는 기존 함정이 같이 사라짐).

### 대형 사업 2~3분기

`durationQuarters` 칸은 이미 여러 분기를 지원합니다 (`GameManager.cs:1005`가 남은 분기만 줄이고 넘어감). 값만 넣으면 됩니다 — **다만 진행 표시(Step 7)를 같이 해야** 플레이어가 2분기짜리 사업을 기다리는 중인지 알 수 있습니다. 표시 없이 기간만 늘리면 그냥 "아무 일도 안 일어나는 분기"가 됩니다.

## Step 5. 착수 조건을 체질 · 성향에 맞게

### 무엇을

`TryStartBusiness()` (`GameManager.cs:1037`) 의 조건은 지금 **금고 ≥ 투자비** 하나뿐입니다. 세 가지를 더합니다.

| 새 조건 | 이유 (기획 근거) |
|---|---|
| 금고가 마이너스면 착수 금지 | 4장 "금고 마이너스 → 위험 시작". 빚진 회사가 새 도박을 벌이면 부도 카운트가 무의미해진다 |
| 투자 후 금고가 운영비 2분기분 밑으로 떨어지면 보류 | 4장 "금고 바닥 → 사업 줄임". 안전 마진 없이 다 지르면 전부 부도난다 |
| 재투자형은 착수 확률 높게, 배당형은 낮게 | 2장 성향 — "번 돈을 다음 사업에 재투자" 가 숫자로 드러나야 한다 |

상수 `BUSINESS_START_CHANCE = 0.25f` 하나를 성향별 둘로 나눕니다 (재투자형 0.35 / 배당형 0.18 정도에서 시작). 40개 평균은 지금과 비슷하게 유지되어 분기당 발표 건수는 크게 안 변합니다.

### 선택 — 성공률에 시대를 얹을지

기존 문서 10장에도 적혀 있던 항목입니다. `IsBoostedByEra(stock)`이면 성공률 +10%p 정도. 기획 5장 "나쁜 체질엔 좋은 시대가 짝으로 있다"를 더 강하게 만들지만, 시대와 사업이 겹쳐서 밸런스 잡기가 어려워집니다. **Step 6에서 숫자를 다 넣고 한 번 돌려본 뒤에 결정**하는 걸 권합니다.

## Step 6. 40개 회사 값 채우기

기획 6장의 칸에 값을 넣는 단계입니다. 여기서부터는 코드가 아니라 **숫자 정하기**라, 체질별 기준표를 먼저 만들고 회사마다 배율로 조정하는 게 빠릅니다.

| 체질 | 평소 매출 | 운영비 | 매출 대비 운영비 | 시작 금고 | 성향 |
|---|---|---|---|---|---|
| 안정형 | 보통 | 적음 | 30% | 운영비 × 4분기 | 주로 배당형 |
| 자원형 | 많음 | 보통 | 60% | 운영비 × 5분기 | 배당/재투자 섞음 |
| 고위험형 | 많음 | 많음 | 95% | 운영비 × 8분기 | 주로 재투자형 |
| 성장형 | 적음 | 많음 | 120% (평소 적자) | 운영비 × 10분기 | 재투자형 |

**"매출 대비 운영비" 하나만 정하면 나머지가 따라옵니다.** 이 비율이 100%를 넘으면 평소 적자, 낮으면 시대가 와도 크게 안 뛰는 회사가 됩니다. 회사마다 매출 절대값은 규모(대형/중형/소형)로 정하고, 이 비율로 성격을 줍니다.

기획 5장의 "나쁜 체질일수록 주가가 싸다"는 `StockBasePrice`를 손대는 게 아니라, **`TotalShare`(발행 주식 수)로 조정**하는 편이 안전합니다. 시가총액 = 현재가 × 발행주식수라서, 주가를 직접 내리면 기존 그래프·뉴스 체감이 다 흔들립니다.

미정으로 남는 숫자는 기획 7장 그대로입니다: 사업별 기간·성공률·보상, 부도 카운트(현재 3/5분기).

## Step 7. 화면에 드러내기

지금 사업은 **전용 UI가 전혀 없고** 분기 발표 팝업의 텍스트 줄이 전부입니다. 새 기획은 체질·부도 위기·진행 중 사업이 플레이어 판단 재료라서, 안 보여주면 시스템이 있어도 없는 것과 같습니다.

### `DetailPanel` (`DetailPanel.cs:60`)

지금 `revenuePrice`라는 칸에 `stock.income`(수입)을 넣고 있습니다. 이름과 내용이 어긋난 상태입니다. 이렇게 정리합니다:

```
평소 매출      120,000 G        ← baseRevenue (사업 성공으로 오른 값)
운영비        − 90,000 G        ← operatingCost
────────────────────────
분기 수입       30,000 G        ← income (시대 보정 포함)
금고           450,000 G        ← runtimeAsset
체질          [성장형] [재투자]  ← 배지
진행 중 사업   미스릴 신광맥 개발 (3분기 중 1분기 남음)
```

금고가 마이너스면 그 줄을 빨갛게 + `연속 3분기 적자 — 부도 위기` 경고를 붙입니다. 기획 4장의 긴장이 여기서 나옵니다.

기획 1장의 정체성(소유주 / 설립 이야기)은 `StockDetailDescription`에 문장으로 넣으면 새 UI 없이 처리됩니다.

### `QuarterReportPanel`

`[부도 위기]`, `[상장폐지]` 줄을 추가합니다. 상폐는 다른 소식에 묻히면 안 되니 팝업 **맨 위로 올리는** 게 좋습니다.

## 시작하기 전에 정해야 할 것 3가지

**① 기획 3장의 "분기 수입 = 평소 매출 − 운영비 + 사업 결과" 에서 '사업 결과'가 무엇인가**
- (A) 성공하면 평소 매출이 영구히 오르는 것만 뜻한다 → 이 문서는 A로 썼습니다
- (B) 그 위에 성공한 분기에만 붙는 일회성 보너스가 따로 있다 → `ActiveBusiness`에 일회성 항목을 추가해야 합니다

**② 시대 배율을 매출에만 걸까, 수입 전체에 걸까**
- 매출에만 (이 문서 권장) → 체질별 성격이 자동으로 생기지만, 성장형 회사의 수입이 분기마다 크게 튑니다
- 수입 전체에 (지금 코드) → 얌전하지만 체질을 나눈 의미가 절반으로 줄어듭니다

**③ 상폐 후 새 회사 상장을 언제 할까**
- 지금 Step 8로 미뤄뒀습니다. "종목이 40개 미만으로 줄어드는 게 싫다"면 Step 3과 묶어야 하고, 작업량이 두 배가 됩니다
